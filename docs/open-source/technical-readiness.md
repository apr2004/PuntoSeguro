# Preparación técnica y seguridad — PuntoSeguro

**Andrea Pérez Rodríguez y Marina Fernández Serrano · Práctica P9 · Revisión: 23 de noviembre de 2026**

**Versión analizada:** rama `main`, commit `113ae8dfcaa0de09a5f4cbd84fe6646a5020a2b6`. Las pruebas y los análisis indicados se realizaron sobre una copia de ese commit. Los resultados describen el estado observado en esa fecha y deben repetirse sobre la versión que se vaya a publicar.

**Decisión propuesta:** el repositorio ya es público, pero todavía no consideramos PuntoSeguro preparado para una apertura completa a usuarios y colaboradores externos ni para tratar datos reales de menores. Antes debemos completar la revisión de datos publicados, evaluar las alertas de dependencias y preparar una configuración de producción segura.

## 2. Secretos y datos sensibles

`.env` está excluido mediante `.gitignore`, pero el proyecto incluye credenciales y una clave JWT de ejemplo para desarrollo. Compose activa el perfil `dev`, que crea cuentas de prueba. Estos valores son conocidos y no deben utilizarse en producción.

Gitleaks señaló una coincidencia en `.env.example`: la clave JWT coincide con la de ejemplo documentada para desarrollo. Se solicitó revisar todas las referencias del clon, pero la herramienta informó de 21 commits analizados y Git identifica 42 commits alcanzables. **La cobertura del historial queda por confirmar**; el resultado no prueba que no existan otras credenciales. El análisis tampoco revisa el contenido de los PDF.

Se extrajo texto de las dos transcripciones de `docs/reuniones/`; una búsqueda automática sencilla no encontró correos ni posibles teléfonos. Aun así, podrían contener nombres u otra información no autorizada para su publicación.

**Decisiones y acciones:** exigir secretos únicos mediante un gestor de secretos o variables del entorno de despliegue; no incluir valores reales en el repositorio ni en el frontend. Repetir el análisis del historial y explicar la diferencia de cobertura. Revisar manualmente las transcripciones y retirarlas de la distribución pública si contienen información no autorizada. Si se detecta una credencial real, revocarla o rotarla y valorar cómo limpiar el historial.

## 4. Configuración y parámetros

La base de datos, el JWT y el proveedor de IA se configuran mediante variables de entorno. Flyway aplica las migraciones y Hibernate valida el esquema. El `compose.yml` actual está orientado al desarrollo: activa `dev`, publica el puerto de PostgreSQL y contiene valores predeterminados de ejemplo.

**Decisión propuesta:** mantener ese Compose para desarrollo y preparar una configuración separada para producción que no active `dev`, rechace secretos ausentes o de ejemplo y limite la conexión a la base de datos. Incorporar TLS, revisar la duración y el almacenamiento de los tokens y evitar respuestas de error con información interna. Antes de usar conversaciones reales, acordar el tratamiento de datos y las condiciones del proveedor externo de IA.
